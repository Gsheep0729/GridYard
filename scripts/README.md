# GridYard 测试脚本

本目录包含 GridYard 项目的自动化测试脚本，用于验证功能和排查问题。

## 脚本说明

### 1. test_loopback.sh - 本机回环测试

最简单的测试脚本，启动两个实例进行基础传输测试。

**使用方法**：

```bash
cd src
./scripts/test_loopback.sh
```

**测试步骤**：
1. 脚本自动启动接收端（端口 35100）和发送端（端口 35101）
2. 在发送端窗口，拖拽文件到接收端的设备卡片
3. 在接收端窗口，点击"接受"按钮
4. 观察传输进度
5. 按 Ctrl+C 停止测试

---

### 2. test_single_machine.sh - 单机多实例测试

更全面的测试脚本，支持多设备场景测试。

**使用方法**：

```bash
cd src
./scripts/test_single_machine.sh
```

**测试内容**：
- 测试 1：启动两个实例（接收端 + 发送端）
- 测试 2：启动三个实例（测试多设备发现）
- 测试 3：创建测试文件并验证传输

**特点**：
- 自动清理测试环境
- 支持交互式测试
- 测试完成后自动退出

## 前置条件

运行测试脚本前，请确保：

1. **项目已构建**：
   ```bash
   cd src
   cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
   cmake --build build -j
   ```

2. **端口未被占用**：
   ```bash
   # 检查端口占用
   lsof -i :35100
   lsof -i :35101

   # 如有占用，先停止进程
   pkill -f appGridYard
   ```

3. **有足够的磁盘空间**（自动化测试会创建临时文件）

## 常见问题

### Q1: 脚本提示"找不到可执行文件"

**原因**：项目未构建或构建目录路径错误

**解决**：
```bash
cd src
cmake --build build -j
```

### Q2: 端口已被占用

**原因**：之前测试的进程未正常退出

**解决**：
```bash
pkill -f appGridYard
```

### Q3: 测试文件创建失败

**原因**：磁盘空间不足或权限问题

**解决**：
```bash
# 检查磁盘空间
df -h /tmp

# 清理临时文件
rm -rf /tmp/gridyard_*
```

### Q4: 实例启动后立即退出

**原因**：可能是配置文件冲突或端口绑定失败

**解决**：
1. 检查日志文件：`logs/gridyard_*.log`
2. 尝试使用不同端口
3. 清理配置文件：`rm -rf /tmp/gridyard_*`

## 命令行参数

GridYard 应用支持以下命令行参数：

| 参数 | 说明 | 示例 |
|------|------|------|
| `--port` | 指定监听端口 | `--port 35100` |
| `--name` | 指定设备名称 | `--name "我的设备"` |
| `--config` | 指定配置文件路径 | `--config /tmp/config.ini` |

**示例**：
```bash
# 启动两个实例，使用不同端口和名称
./build/client/appGridYard --port 35100 --name "接收端" &
./build/client/appGridYard --port 35101 --name "发送端" &
```

---

## 注意事项

1. **测试环境隔离**：脚本使用 `/tmp` 目录存放临时文件，测试完成后自动清理

2. **进程管理**：脚本会自动杀死测试进程，但如果脚本异常退出，可能需要手动清理：
   ```bash
   pkill -f appGridYard
   ```

3. **日志查看**：测试过程中生成的日志文件位于 `logs/` 目录

4. **并发测试**：避免同时运行多个测试脚本，可能导致端口冲突
