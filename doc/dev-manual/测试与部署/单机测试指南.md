# GridYard 单机测试指南

## 问题背景

GridYard 是局域网 P2P 文件传输软件，需要多台设备测试。但开发阶段通常只有一台电脑，本文档提供单机测试方案。

---

## 方案一：多实例测试（推荐）

### 原理

在同一台机器上启动多个 GridYard 实例，使用不同端口和配置文件，模拟多设备环境。

### 操作步骤

#### 1. 构建项目

```bash
cmake --build src/build-ninja -j
```

#### 2. 启动两个实例（基本测试）

**终端 1 - 接收端：**
```bash
./src/build-ninja/client/appGridYard \
  --config ~/gridyard_receiver.ini \
  --port 35100 \
  --name "接收端"
```

**终端 2 - 发送端：**
```bash
./src/build-ninja/client/appGridYard \
  --config ~/gridyard_sender.ini \
  --port 35101 \
  --name "发送端"
```

`--config` 必须使用两个不同且稳定的路径。不要省略 `--config`，否则设备 ID 可能因为临时配置被清理而变化，导致历史记录无法挂到原设备上。

#### 3. 测试流程

1. **设备发现**：等待 3-5 秒，检查两个窗口是否都能看到对方设备
2. **文件传输**：
   - 在发送端窗口，将文件拖拽到接收端的设备卡片上
   - 或选中接收端设备，在会话页发送菜单中选择"发送文件"或"发送文件夹"
   - 观察接收端是否弹出确认对话框
   - 点击"接受"，观察传输进度
3. **传输完成**：检查接收端设置页中的接收路径是否有文件

#### 4. 启动三个实例（多设备测试）

```bash
# 终端 1
./src/build-ninja/client/appGridYard --config ~/gridyard_a.ini --port 35100 --name "设备A" &

# 终端 2
./src/build-ninja/client/appGridYard --config ~/gridyard_b.ini --port 35101 --name "设备B" &

# 终端 3
./src/build-ninja/client/appGridYard --config ~/gridyard_c.ini --port 35102 --name "设备C" &
```

测试场景：
- A → B 发送文件
- B → C 发送文件
- C → A 发送文件
- A → B 和 A → C 同时发送

## 方案二：自动化测试脚本

### 使用方法

```bash
# 赋予执行权限
chmod +x scripts/test_single_machine.sh

# 运行测试脚本
./scripts/test_single_machine.sh
```

脚本会自动：
1. 启动多个实例
2. 引导你进行测试
3. 测试完成后自动清理

- [ ] 多文件传输成功
- [ ] 目录传输成功
- [ ] 发送菜单的"发送文件"能打开文件选择器并支持多选
- [ ] 发送菜单的"发送文件夹"能打开文件夹选择器
- [ ] 设置页"更改目录"能打开文件夹选择器并保存接收路径
- [ ] 大文件传输（>100MB）
- [ ] 零字节文件传输
- [ ] 中文、空格和特殊字符文件名
- [ ] 中文、空格和特殊字符目录名
- [ ] SHA-256 校验正确
- [ ] 传输进度显示正确
- [ ] 取消传输功能

### 异常处理

- [ ] 网络断开超时处理
- [ ] 接收端拒绝传输
- [ ] 磁盘空间不足提示
- [ ] 文件名冲突处理

### UI 功能

- [ ] 拖拽传输
- [ ] 传输面板显示
- [ ] 完成提示弹窗
- [ ] 打开文件所在目录

### 本地历史与异常恢复

- [ ] 空库首次启动后自动创建数据库和 4 张业务表
- [ ] 重复启动不丢失已有设备、聊天和传输历史
- [ ] 聊天收发后重启仍可查询历史
- [ ] 文件或文件夹传输完成后重启仍可查询历史
- [ ] 保留期限清理只删除过期历史，不删除设备目录和真实文件
- [ ] 数据库锁定或写入失败时，聊天和文件传输主链路不崩溃
- [ ] 损坏数据库会备份为 `.corrupt-{timestamp}` 并重建空库
- [ ] 日志不包含聊天正文、完整 SQL、绑定参数或完整文件路径

### 托盘与通知

- [ ] 关闭窗口后应用进入托盘后台运行
- [ ] 托盘菜单可以显示窗口、隐藏窗口和退出应用
- [ ] 聊天消息、传输请求和传输完成有非阻塞通知
- [ ] 通知不显示完整文件路径

## 常见问题

### Q1: 两个实例设备名相同怎么办？

使用 `--name` 参数指定不同名称：
```bash
./src/build-ninja/client/appGridYard --config ~/gridyard_a.ini --port 35100 --name "设备A"
./src/build-ninja/client/appGridYard --config ~/gridyard_b.ini --port 35101 --name "设备B"
```

### Q2: 设备发现不到对方？

1. 检查防火墙设置，允许 UDP 端口 45678
2. 确保两个实例使用不同端口
3. 确保两个实例使用不同 `--config` 文件
4. 等待 5-10 秒让广播生效

### Q3: 传输失败？

1. 检查日志文件：`logs/gridyard_YYYYMMDD.log`
2. 确认接收端已接受传输
3. 检查磁盘空间是否充足

### Q4: 如何查看详细日志？

日志文件位于可执行文件同级的 `logs/` 文件夹，开发构建默认是 `src/build-ninja/client/logs/`，格式：
```
[2026-06-05 12:26:18.639] [DEBUG] [P2pServer] 监听端口 35100 成功
```

## 调试技巧

### 1. 启用详细日志

在代码中添加：
```cpp
qDebug() << "调试信息";
```

### 2. 使用 Qt Creator 调试

1. 打开 Qt Creator
2. 加载项目 `src/CMakeLists.txt`
3. 设置断点
4. 以调试模式运行

### 3. 网络抓包

```bash
# 监听 UDP 广播
sudo tcpdump -i any udp port 45678

# 监听 TCP 传输
sudo tcpdump -i any tcp port 35100
```

## 测试环境要求

- **操作系统**：Linux（推荐 Manjaro）
- **网络**：至少一个活跃的网络接口
- **磁盘**：至少 1GB 可用空间（测试大文件传输）
- **Qt 版本**：6.10+，需要 Quick、QuickControls2、QuickDialogs2、Network、Sql 模块
