# GridYard 单机测试指南

本文档用于在一台 Linux 机器上验证 GridYard v6.8.1。单机测试通过启动多个实例并使用不同端口、不同配置文件模拟多台设备；发布版 AppImage 和压缩包同样适用。

## 测试目标

- 验证两个或多个实例能互相发现。
- 验证聊天、文件、文件夹传输和传输历史。
- 验证配置、数据库和日志使用系统标准目录持久化。
- 验证设备别名、接收路径等配置重启后不丢失。

## 运行时数据目录

GridYard v6.8.1 不再把配置、数据库或日志写到 AppImage/压缩包同级目录。默认路径如下：

| 数据 | Linux 默认路径 |
|:-----|:---------------|
| 配置文件 | `~/.config/CQNU-SED/GridYard/gridyard.ini` |
| 数据库 | `~/.local/share/CQNU-SED/GridYard/database/gridyard-history.sqlite` |
| 日志 | `~/.local/share/CQNU-SED/GridYard/logs/gridyard_YYYYMMDD.log` |

使用 `--config <path>` 时，只有配置文件路径被覆盖；数据库和日志仍使用系统应用数据目录。

## 启动方式

### 开发构建

```bash
cmake --build build-ninja
```

接收端：

```bash
./build-ninja/client/appGridYard \
  --config ~/gridyard_receiver.ini \
  --port 35100 \
  --name "接收端"
```

发送端：

```bash
./build-ninja/client/appGridYard \
  --config ~/gridyard_sender.ini \
  --port 35101 \
  --name "发送端"
```

### AppImage

```bash
cd release/v6.8.1
chmod +x GridYard-v6.8.1-x86_64.AppImage
```

接收端：

```bash
./GridYard-v6.8.1-x86_64.AppImage \
  --config ~/gridyard_receiver.ini \
  --port 35100 \
  --name "接收端"
```

发送端：

```bash
./GridYard-v6.8.1-x86_64.AppImage \
  --config ~/gridyard_sender.ini \
  --port 35101 \
  --name "发送端"
```

### 压缩包

解压发布包后，优先运行包内 `AppRun`。如果直接运行 `usr/bin/appGridYard`，也建议用不同 `--config` 和 `--port` 做多实例测试。

```bash
./AppRun --config ~/gridyard_receiver.ini --port 35100 --name "接收端"
./AppRun --config ~/gridyard_sender.ini --port 35101 --name "发送端"
```

## 多实例规则

- 同一台机器启动多个实例时，每个实例必须使用不同 TCP 端口。
- 多实例测试建议每个实例使用不同且稳定的 `--config` 文件，避免共用同一设备身份。
- 单实例正常使用可以不传 `--config`，程序会使用系统默认配置目录。
- 默认 UDP 发现端口为 `45678`，P2P TCP 默认端口为 `35100`。

三实例示例：

```bash
./build-ninja/client/appGridYard --config ~/gridyard_a.ini --port 35100 --name "设备A" &
./build-ninja/client/appGridYard --config ~/gridyard_b.ini --port 35101 --name "设备B" &
./build-ninja/client/appGridYard --config ~/gridyard_c.ini --port 35102 --name "设备C" &
```

可验证 A 到 B、B 到 C、C 到 A，以及 A 同时向 B/C 发送。

## 基础验收流程

### 1. 设备发现

1. 启动两个实例。
2. 等待 3-5 秒。
3. 检查两个窗口设备列表是否都能看到对方。
4. 确认设备在线状态、设备名、IP 和端口显示合理。

### 2. 在线聊天

1. 在发送端选中接收端设备。
2. 发送一条普通文本消息。
3. 发送一条包含中文、空格和标点的消息。
4. 确认接收端能实时显示。
5. 关闭并重启两个实例，确认聊天历史仍可恢复。

### 3. 文件传输专项流程

#### 拖拽单文件

1. 在发送端，从文件管理器拖拽一个 1-10MB 文件到接收端设备卡片。
2. 接收端应弹出确认对话框。
3. 点击接受，观察发送端和接收端传输进度。
4. 传输完成后，检查接收路径中存在该文件。

#### 发送菜单多文件

1. 在发送端选中接收端设备，进入右侧会话页。
2. 点击发送菜单，选择“发送文件”。
3. 一次选择 2-3 个文件，至少包含一个中文或空格文件名。
4. 接收端接受传输，确认所有文件都完成。

#### 文件夹传输

1. 在发送端点击发送菜单，选择“发送文件夹”。
2. 选择一个包含子目录、空文件、中文文件名和空格文件名的目录。
3. 接收端接受传输。
4. 传输完成后检查目录结构、空文件和文件名是否保持一致。

#### 接收路径

1. 在接收端打开设置页。
2. 点击“更改目录”，选择一个路径中包含中文或空格的目录。
3. 保存设置后重新发送一个文件。
4. 确认文件保存到新接收路径。
5. 重启接收端，确认接收路径仍保持不变。

#### 传输历史

1. 完成文件或文件夹传输后，打开传输历史。
2. 确认记录包含对端设备、文件名、大小、状态和时间。
3. 重启应用后再次查看传输历史。
4. 删除某条历史记录，确认只删除历史，不删除真实文件。

## 发布版持久化验证

按最终 v6.8.1 发布包验证以下项目：

| 测试项 | 期望结果 |
|:------|:---------|
| `--config` 参数 | `/tmp/config_test/test.ini` 能正确创建 |
| 系统默认配置目录 | `~/.config/CQNU-SED/GridYard/gridyard.ini` 存在 |
| 系统默认数据库 | `~/.local/share/CQNU-SED/GridYard/database/` 有 SQLite 文件 |
| 系统默认日志 | `~/.local/share/CQNU-SED/GridYard/logs/` 有日志文件 |
| 设备别名持久化 | 修改设备名后重启仍保持新名称 |

示例命令：

```bash
rm -rf /tmp/config_test
mkdir -p /tmp/config_test
./release/v6.8.1/GridYard-v6.8.1-x86_64.AppImage \
  --config /tmp/config_test/test.ini \
  --port 35100 \
  --name "GY-PC"
```

检查：

```bash
test -f /tmp/config_test/test.ini
test -f "$HOME/.config/CQNU-SED/GridYard/gridyard.ini"
find "$HOME/.local/share/CQNU-SED/GridYard/database" -name '*.sqlite' -print
find "$HOME/.local/share/CQNU-SED/GridYard/logs" -name 'gridyard_*.log' -print
```

- [ ] 设备上线/离线状态更新

### 聊天

- [ ] 文本消息实时收发
- [ ] 中文、空格和标点显示正常
- [ ] 重启后聊天历史恢复
- [ ] 删除聊天历史只影响当前设备会话

### 文件传输

- [ ] 单文件传输成功
- [ ] 多文件传输成功
- [ ] 文件夹传输成功
- [ ] 大文件传输成功
- [ ] 零字节文件传输成功
- [ ] 中文、空格和特殊字符文件名正常
- [ ] SHA-256 校验正确
- [ ] 传输进度显示正确
- [ ] 取消传输功能正常
- [ ] 拒绝接收后发送端显示失败或拒绝状态

### 本地历史与异常恢复

- [ ] 空库首次启动后自动创建数据库和业务表
- [ ] 重复启动不丢失已有设备、聊天和传输历史
- [ ] 文件或文件夹传输完成后重启仍可查询历史

- [ ] 关闭窗口后应用进入托盘后台运行
- [ ] 托盘菜单可以显示窗口、隐藏窗口和退出应用

- [ ] 通知不显示完整文件路径

## 常见问题

### Q1: 两个实例设备名相同怎么办？

使用 `--name` 参数指定不同名称，并使用不同 `--config` 文件：

```bash
./build-ninja/client/appGridYard --config ~/gridyard_a.ini --port 35100 --name "设备A"
./build-ninja/client/appGridYard --config ~/gridyard_b.ini --port 35101 --name "设备B"
```

### Q2: 设备发现不到对方？

1. 检查防火墙是否允许 UDP `45678`。
2. 确保两个实例使用不同 TCP 端口。
3. 确保两个实例使用不同 `--config` 文件。
4. 等待 5-10 秒让广播和心跳刷新。

### Q3: 文件传输失败？

1. 查看系统日志目录中的 `gridyard_YYYYMMDD.log`。
2. 确认接收端已接受传输。
3. 检查接收路径是否存在且可写。
4. 检查磁盘空间是否充足。
5. 确认防火墙没有阻止 TCP 传输端口。

### Q4: 点击发送文件或发送文件夹没有弹出选择器？

1. 确认构建已链接 `Qt6::QuickDialogs2`。
2. AppImage/压缩包中应包含 Qt Quick Dialogs QML 模块和平台插件。
3. 从终端启动程序，查看是否有 `QtQuick.Dialogs` 导入失败日志。

### Q5: 如何查看详细日志？

日志文件位于系统应用数据目录的 `logs/` 文件夹，Linux 默认是：

```text
~/.local/share/CQNU-SED/GridYard/logs/
```

日志格式示例：

```text
[2026-06-29 17:02:00.000] [DEBUG] [P2pServer] 监听端口 35100 成功
```

## 调试技巧

网络抓包：

```bash
sudo tcpdump -i any udp port 45678
sudo tcpdump -i any tcp port 35100
```

清理系统默认运行数据：

```bash
rm -rf "$HOME/.config/CQNU-SED/GridYard"
rm -rf "$HOME/.local/share/CQNU-SED/GridYard"
```

只清理多实例测试配置：

```bash
rm -f ~/gridyard_receiver.ini ~/gridyard_sender.ini ~/gridyard_a.ini ~/gridyard_b.ini ~/gridyard_c.ini
```

## 测试环境要求

- 操作系统：Linux x86_64，推荐 Manjaro 或同类桌面环境
- 网络：至少一个活跃网络接口
- 磁盘：至少 1GB 可用空间，大文件测试需更多空间
- Qt 版本：6.10+，需要 Quick、QuickControls2、QuickDialogs2、Network、Sql、Widgets 模块
