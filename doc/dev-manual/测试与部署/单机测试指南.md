# GridYard 单机测试指南

## 问题背景

GridYard 是局域网 P2P 文件传输软件，需要多台设备测试。但开发阶段通常只有一台电脑，本文档提供单机测试方案。

---

## 方案一：多实例测试（推荐）

### 原理

在同一台机器上启动多个 GridYard 实例，使用不同端口和配置文件，模拟多设备环境。

### 操作步骤

#### 1. 构建项目

```bash
cd src
cmake --build build-ninja -j
```

#### 2. 启动两个实例（基本测试）

**终端 1 - 接收端：**
```bash
./build-ninja/client/appGridYard --port 35100 --name "接收端"
```

**终端 2 - 发送端：**
```bash
./build-ninja/client/appGridYard --port 35101 --name "发送端"
```

#### 3. 测试流程

1. **设备发现**：等待 3-5 秒，检查两个窗口是否都能看到对方设备
2. **文件传输**：
   - 在发送端窗口，将文件拖拽到接收端的设备卡片上
   - 观察接收端是否弹出确认对话框
   - 点击"接受"，观察传输进度
3. **传输完成**：检查接收端默认路径 `~/GridYard/document` 是否有文件

#### 4. 启动三个实例（多设备测试）

```bash
# 终端 1
./build-ninja/client/appGridYard --port 35100 --name "设备A" &

# 终端 2
./build-ninja/client/appGridYard --port 35101 --name "设备B" &

# 终端 3
./build-ninja/client/appGridYard --port 35102 --name "设备C" &
```

测试场景：
- A → B 发送文件
- B → C 发送文件
- C → A 发送文件
- A → B 和 A → C 同时发送

## 方案二：自动化测试脚本

### 使用方法

```bash
# 赋予执行权限
chmod +x scripts/test_single_machine.sh

# 运行测试脚本
./scripts/test_single_machine.sh
```

脚本会自动：
1. 启动多个实例
2. 引导你进行测试
3. 测试完成后自动清理

## 测试检查清单

### 基础功能

- [ ] 程序启动不崩溃
- [ ] 设备名显示正确
- [ ] IP 地址显示正确
- [ ] 端口配置生效

### 设备发现

- [ ] UDP 广播正常发送
- [ ] 能发现同局域网设备
- [ ] 设备上线/离线状态更新
- [ ] 心跳超时剔除（15秒）

### 文件传输

- [ ] 单文件传输成功
- [ ] 多文件传输成功
- [ ] 目录传输成功
- [ ] 大文件传输（>100MB）
- [ ] 零字节文件传输
- [ ] 特殊字符文件名
- [ ] SHA-256 校验正确
- [ ] 传输进度显示正确
- [ ] 取消传输功能

### 异常处理

- [ ] 网络断开超时处理
- [ ] 接收端拒绝传输
- [ ] 磁盘空间不足提示
- [ ] 文件名冲突处理

### UI 功能

- [ ] 拖拽传输
- [ ] 传输面板显示
- [ ] 完成提示弹窗
- [ ] 打开文件所在目录

### 本地历史与异常恢复

- [ ] 空库首次启动后自动创建数据库和 4 张业务表
- [ ] 重复启动不丢失已有设备、聊天和传输历史
- [ ] 聊天收发后重启仍可查询历史
- [ ] 文件或文件夹传输完成后重启仍可查询历史
- [ ] 保留期限清理只删除过期历史，不删除设备目录和真实文件
- [ ] 数据库锁定或写入失败时，聊天和文件传输主链路不崩溃
- [ ] 损坏数据库会备份为 `.corrupt-{timestamp}` 并重建空库
- [ ] 日志不包含聊天正文、完整 SQL、绑定参数或完整文件路径

### 托盘与通知

- [ ] 关闭窗口后应用进入托盘后台运行
- [ ] 托盘菜单可以显示窗口、隐藏窗口和退出应用
- [ ] 聊天消息、传输请求和传输完成有非阻塞通知
- [ ] 通知不显示完整文件路径

## 常见问题

### Q1: 两个实例设备名相同怎么办？

使用 `--name` 参数指定不同名称：
```bash
./build-ninja/client/appGridYard --port 35100 --name "设备A"
./build-ninja/client/appGridYard --port 35101 --name "设备B"
```

### Q2: 设备发现不到对方？

1. 检查防火墙设置，允许 UDP 端口 45678
2. 确保两个实例使用不同端口
3. 等待 5-10 秒让广播生效

### Q3: 传输失败？

1. 检查日志文件：`logs/gridyard_YYYYMMDD.log`
2. 确认接收端已接受传输
3. 检查磁盘空间是否充足

### Q4: 如何查看详细日志？

日志文件位于仓库根目录 `logs/` 文件夹，格式：
```
[2026-06-05 12:26:18.639] [DEBUG] [P2pServer] 监听端口 35100 成功
```

## 调试技巧

### 1. 启用详细日志

在代码中添加：
```cpp
qDebug() << "调试信息";
```

### 2. 使用 Qt Creator 调试

1. 打开 Qt Creator
2. 加载项目 `src/CMakeLists.txt`
3. 设置断点
4. 以调试模式运行

### 3. 网络抓包

```bash
# 监听 UDP 广播
sudo tcpdump -i any udp port 45678

# 监听 TCP 传输
sudo tcpdump -i any tcp port 35100
```

## 测试环境要求

- **操作系统**：Linux（推荐 Manjaro）
- **网络**：至少一个活跃的网络接口
- **磁盘**：至少 1GB 可用空间（测试大文件传输）
- **Qt 版本**：6.10+
