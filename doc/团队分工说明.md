# GridYard 团队分工说明

> 本文档用于说明 GridYard 课程项目开发过程中三名成员的主要负责范围、协作方式和阶段投入情况。

## 团队成员

| 成员 | 学号与 Git 标识 | 主要方向 | 主要负责内容 |
|------|----------------|----------|--------------|
| 高扬 | 2024051604085GaoYang | 核心成员、全阶段参与、架构收口 | 项目结构设计、TLV 协议与编解码、核心控制器拆分、CMake 构建、打包部署、版本同步、接口文档、阶段验收，以及各阶段联调和问题收口 |
| 冯春霖 | 2024051604119FengChunlin | 网络、传输、多线程、持久化联调 | UDP 设备发现、P2P 连接、文件发送/接收 Worker、聊天连接管理、传输异常处理、历史数据接入和联调修复 |
| 杜若贤 | 2024051604062DuRuoxian | QML 界面、交互体验、可视化呈现 | 设备列表、传输面板、会话页、聊天气泡、设置弹窗、传输历史视图、界面状态和视觉细节调整 |

实际开发中三个人不是完全按文件夹切开工作。高扬作为核心成员，基本每个阶段都会参与一点：前期搭结构，中期处理协议、构建和跨模块接口，后期负责收口、联调和验收。冯春霖和杜若贤各自主责更集中，但在功能落地时也会配合补测试、修问题或调整接口，因此同一阶段的提交会有交叉。

## 分工原则

1. **先按模块主责划分**：高扬作为核心成员贯穿全阶段，主要负责架构、协议、构建、发布和跨模块收口；网络传输、Socket 生命周期和 Worker 逻辑由冯春霖主导；QML 页面和用户交互由杜若贤主导。
2. **再按风险点归属**：如果一个提交同时改了 UI 和核心逻辑，以主要风险点为准。例如首帧分流虽然会影响界面表现，但核心风险在连接路由，所以归网络侧；会话页整合虽然会改控制器接口，但主要风险在用户交互，所以归界面侧。
3. **允许少量交叉**：版本同步、注释、文档、联调修复会穿插在各模块里，不强行保证每个人只改自己的目录。

## 阶段分工

### 1. 项目初始化与工程骨架

高扬主要负责项目目录、CMake 分层、`client/shared/server/tests` 的基础结构，以及 README 和早期技术文档整理。这个阶段高扬投入最多，重点是先把项目搭起来，让后续模块可以并行推进。

冯春霖参与了客户端启动配置、基础控制器接入和 gitignore/构建问题修复，保证不同机器拉取后能正常构建。

杜若贤主要负责早期 QML 根界面、设备列表的雏形，以及类图、组件图等辅助设计材料。

### 2. 协议层与设备发现

高扬负责 TLV 帧格式、`FrameCodec` 粘包/半包处理、共享数据结构和协议边界设计，也参与设备发现和传输链路的接口衔接。后续协议错误码、Payload 上限、防护策略也主要由高扬收口。

冯春霖负责 `DiscoveryService`、UDP 广播、设备在线状态维护和多实例测试相关问题。设备发现涉及网络环境、真实 IP、多网卡和端口监听，因此主要由网络侧持续跟进。

杜若贤负责设备卡片、设备列表和设置弹窗，把底层发现到的设备信息展示出来，并处理空状态、刷新状态和基础交互。

### 3. 文件传输与健壮性

冯春霖主导 `P2pServer`、`FileSenderWorker`、`FileReceiverWorker`、文件夹传输、SHA-256 校验、超时检测、磁盘空间不足、零字节文件等传输链路问题。

高扬负责 `TransferSessionManager`、目录序列化工具、传输状态收口、日志系统和 AppImage 打包，也参与文件夹传输、真实 IP、单机多实例测试等问题的联调。传输链路里跨线程信号、任务状态、协议错误码这些问题主要由高扬和冯春霖一起处理。

杜若贤负责接收确认弹窗、传输任务卡片、文件/文件夹图标、传输记录展示、删除确认和文件夹展开预览等体验细节。

### 4. 在线聊天

高扬负责聊天消息协议、共享消息结构、序列化边界、版本同步和在线聊天阶段验收，同时参与会话页和聊天连接之间的接口协调。

冯春霖负责聊天连接管理、首帧分流、`ChatConnection`、`ChatManager`、Socket 生命周期、断线重连和聊天消息收发联调。

杜若贤负责聊天气泡、消息模型展示、会话页输入框、空状态文案和会话流整合。聊天功能落地时，界面和网络需要频繁联调，因此这个阶段三个人交叉比较多。

### 5. 本地数据层与历史恢复

高扬负责本地数据层的整体结构设计，包括领域端口、SQLite 迁移基础、数据库 Broker、应用启动组合根调整和 API 文档收口，也参与历史恢复、托盘状态和异常降级的整体联调。

冯春霖负责设备目录、聊天消息、传输历史的持久化接入和历史恢复联调，包括异步写入、仓储测试、异常恢复和跨重启查询。

杜若贤负责历史视图、保留清理设置、本地历史不可用状态、托盘通知相关界面提示和会话体验调整。

### 6. 收尾与发布

高扬主要处理 CMake 构建结构、运行时数据目录策略、AppController 组合根、版本号同步、接口文档和发布前验收。最后阶段基本每个模块都有高扬参与检查或收口，保证版本、文档、构建和运行路径一致。

冯春霖主要处理最后阶段的跨模块 Bug、文件路径转换、传输/聊天链路兼容和最终联调。

杜若贤主要处理统一会话流、传输和聊天页面合并、QuickDialogs2 文件选择器相关界面交互，以及页面细节收尾。

## 协作方式

- 每个阶段先由对应主责成员实现核心逻辑，再由另外两名成员做联调、测试或文档补充。
- 大功能通常按“协议/数据结构 -> 后端控制器/网络链路 -> QML 展示和交互 -> 测试与文档”的顺序推进。
- 遇到跨模块问题时优先按风险点分工：网络异常由冯春霖排查，架构和构建问题由高扬处理，界面状态和交互问题由杜若贤修正。
- 因开发时存在共用开发环境和集中提交的情况，Git 提交作者不能完全等同于每一行代码的实际参与情况，本文档以模块主责和实际协作过程为准。

## 总结

整体投入上，高扬是贯穿全阶段的核心成员，除了架构、协议、构建和发布收口，也会参与各模块联调和关键问题处理；冯春霖承担了网络传输、聊天连接和持久化联调等核心功能；杜若贤主要负责用户可见的 QML 界面和交互体验。三个人的工作有主次分工，但不是孤立开发，很多功能都是在主责成员完成核心实现后，通过联调和体验修正逐步稳定下来的。
