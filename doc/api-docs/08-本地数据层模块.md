## 模块概述

本地数据层为 GridYard 客户端提供可选的 SQLite 历史能力，保存设备目录、聊天消息和已结束传输记录。该模块不参与文件内容传输，不提供离线消息队列，也不依赖账号或服务端。

核心边界：

- QML 只能通过 `AppController.history` 和现有模型访问历史功能；
- 应用层只依赖 Repository 接口和值对象；
- SQL 只允许出现在 `src/client/storage/*.cpp`；
- 数据库不可用时进入无历史模式，发现、聊天和文件传输继续运行。

## 基础设施实现

| 类型 | 职责 |
|:-----|:-----|
| `SqliteDatabaseProxy` | 检查 QSQLITE 驱动，打开数据库，设置 WAL、foreign_keys、busy_timeout，执行 migration，管理每线程命名连接 |
| `MigrationRunner` | 创建 `schema_version`，执行版本 1 schema 迁移 |
| `SqliteDeviceProxy` | 设备目录 upsert、活动时间更新、最近设备查询 |
| `SqliteMessageProxy` | 聊天消息幂等保存、游标分页、删除和过期清理 |
| `SqliteTransferHistoryProxy` | 结束态传输历史 upsert、筛选查询、删除和过期清理 |
| `DatabaseWorker` | 在专用线程串行执行存储任务，退出前排空已提交任务 |

## 应用层入口

`AppController` 负责创建存储代理、Repository Proxy 和 `HistoryController`，并把聊天、传输、设备发现事件转换为异步存储任务。

`HistoryController` 负责向 QML 暴露历史用例：

| 接口 | 说明 |
|:-----|:-----|
| `loadMoreMessages(deviceId)` | 按当前聊天模型第一条记录生成游标，加载更早消息 |
| `queryTransfers(filter)` | 按设备、状态和时间查询传输历史 |
| `deleteMessage(deviceId, messageId)` | 删除单条聊天记录并同步内存模型 |
| `deleteConversation(deviceId)` | 清空指定设备会话 |
| `deleteTransfer(recordId)` | 删除一条传输历史，不删除真实文件 |
| `clearAllMessages()` | 清空聊天历史，保留设备目录 |
| `clearAllTransfers()` | 清空传输历史，保留设备目录 |
| `setRetentionDays(days)` | 设置历史保留期限，`0` 表示永久保留 |
| `cleanupExpiredRecords()` | 清理过期聊天和传输历史 |

## 异常与降级

| 场景 | 行为 |
|:-----|:-----|
| 缺少 `QSQLITE` 驱动 | 初始化失败，`localHistoryAvailable=false`，P2P 主链路继续 |
| 空数据库首次启动 | 自动创建 schema_version 和 4 张业务表 |
| 重复 migration | 跳过已应用版本，不丢失已有数据 |
| 数据库锁定 | 当前任务失败并上报非阻塞提示，后续任务可重试 |
| 数据库损坏 | 备份为 `.corrupt-{timestamp}` 后重建空库 |
| 写入失败 | 不改变聊天或传输的网络结果，只提示历史可能缺失 |

日志只能记录操作类型、错误类别和脱敏标识，不记录聊天正文、完整 SQL、绑定参数或完整文件路径。
