## 模块概述

本地数据层为 GridYard 客户端提供可选的 SQLite 历史能力，保存设备目录、聊天消息和已结束传输记录。该模块不参与文件内容传输，不提供离线消息队列，也不依赖账号或服务端。

核心边界：

- QML 只能通过 `AppController.historyController` 和现有模型访问历史功能；
- 应用层只依赖 Repository 接口和值对象；
- SQL 只允许出现在 `src/client/storage/*.cpp`；
- 数据库不可用时进入无历史模式，发现、聊天和文件传输继续运行。

## 基础设施实现

| 类型 | 职责 |
|:-----|:-----|
| `LocalDataBroker` | 收拢 SQLite 初始化、Repository 和 DatabaseWorker 的创建与生命周期，向应用层提供语义化历史入口 |
| `SqliteDatabaseBroker` | 检查 QSQLITE 驱动，打开数据库，设置 WAL、foreign_keys、busy_timeout，执行 migration，管理每线程命名连接 |
| `MigrationRunner` | 创建 `schema_version`，执行版本 1 schema 迁移 |
| `SqliteDeviceRepository` | 设备目录 upsert、活动时间更新、最近设备查询 |
| `SqliteMessageRepository` | 聊天消息幂等保存、游标分页、删除和过期清理 |
| `SqliteTransferHistoryRepository` | 结束态传输历史 upsert、筛选查询、删除和过期清理 |
| `DatabaseWorker` | 在专用线程串行执行存储任务，退出前排空已提交任务 |

## 应用层入口

`AppController` 负责创建 `LocalDataBroker` 和 `HistoryController`，并把聊天、传输、设备发现事件转换为异步存储任务。`HistoryController` 通过 `LocalDataBroker` 访问本地历史数据，不直接持有 `DatabaseWorker` 或 Repository。

`HistoryController` 负责向 QML 暴露历史用例：

| 接口 | 说明 |
|:-----|:-----|
| `loadMoreMessages(deviceId)` | 按当前聊天模型第一条记录生成游标，加载更早消息 |
| `queryTransfers(filter)` | 按设备、状态和时间查询传输历史 |
| `deleteMessage(deviceId, messageId)` | 删除单条聊天记录并同步内存模型 |
| `deleteConversation(deviceId)` | 清空指定设备会话 |
| `deleteTransfer(recordId)` | 删除一条传输历史，不删除真实文件 |
| `clearAllMessages()` | 清空聊天历史，保留设备目录 |
| `clearAllTransfers()` | 清空传输历史，保留设备目录 |
| `setRetentionDays(days)` | 设置历史保留期限，`0` 表示永久保留 |
| `cleanupExpiredRecords()` | 清理过期聊天和传输历史 |

## 数据库文件与连接参数

应用启动时由 `AppController` 初始化数据库：

```cpp
_storage->initialize(ApplicationPaths::databaseDir() + "/gridyard-history.sqlite", &storageError);
```

数据库路径：

```text
<QStandardPaths::AppDataLocation>/database/gridyard-history.sqlite
```

`ApplicationPaths::databaseDir()` 会确保 `database` 子目录存在。测试代码可用 `ApplicationPaths::coverForTest(baseDir)` 覆盖数据根目录。

`SqliteDatabaseBroker` 为每个线程创建独立命名连接，不跨线程传递 `QSqlDatabase`。每次打开连接都会设置：

| PRAGMA | 值 | 说明 |
|:-----|:-----|:-----|
| `foreign_keys` | `ON` | 启用外键约束 |
| `journal_mode` | `WAL` | 使用 WAL 日志 |
| `synchronous` | `NORMAL` | 平衡性能和持久化安全 |
| `busy_timeout` | `5000` | 锁竞争最多等待 5 秒 |

## 数据库设计

### 表关系

```text
peer_devices
  ├─ 1:1 chat_conversations
  │      └─ 1:N chat_messages
  └─ 1:N transfer_history
```

聊天记录和传输历史都挂在“对端 `device_id`”下，不按设备名、IP 或端口归属。

### `schema_version`

| 字段 | 类型 | 约束 | 说明 |
|:-----|:-----|:-----|:-----|
| `version` | `INTEGER` | `PRIMARY KEY` | 已应用迁移版本 |
| `applied_at` | `TEXT` | `NOT NULL` | 迁移应用 UTC 时间 |

### `peer_devices`

| 字段 | 类型 | 约束 | 说明 |
|:-----|:-----|:-----|:-----|
| `device_id` | `TEXT` | `PRIMARY KEY NOT NULL` | 对端稳定设备 ID |
| `device_name` | `TEXT` | `NOT NULL` | 最近一次发现的设备名 |
| `last_ip_address` | `TEXT` | 可空 | 最近一次发现 IP |
| `last_tcp_port` | `INTEGER` | 可空 | 最近一次 TCP 端口 |
| `first_seen_at` | `TEXT` | `NOT NULL` | 首次发现 UTC 时间 |
| `last_seen_at` | `TEXT` | `NOT NULL` | 最近发现 UTC 时间 |
| `last_chat_at` | `TEXT` | 可空 | 最近聊天活动 UTC 时间 |
| `last_transfer_at` | `TEXT` | 可空 | 最近传输活动 UTC 时间 |

### `chat_conversations`

| 字段 | 类型 | 约束 | 说明 |
|:-----|:-----|:-----|:-----|
| `peer_device_id` | `TEXT` | `PRIMARY KEY NOT NULL`，外键到 `peer_devices(device_id)`，`ON DELETE CASCADE` | 一个对端设备一条会话 |
| `created_at` | `TEXT` | `NOT NULL` | 会话创建 UTC 时间 |
| `last_message_at` | `TEXT` | `NOT NULL` | 最近消息 UTC 时间 |

删除 `chat_conversations` 行会级联删除该设备的 `chat_messages`。

### `chat_messages`

| 字段 | 类型 | 约束 | 说明 |
|:-----|:-----|:-----|:-----|
| `message_id` | `TEXT` | `PRIMARY KEY NOT NULL` | 消息 UUID，幂等写入键 |
| `peer_device_id` | `TEXT` | `NOT NULL`，外键到 `chat_conversations(peer_device_id)`，`ON DELETE CASCADE` | 对端设备 ID |
| `direction` | `INTEGER` | `CHECK (direction IN (0, 1))` | `0` 接收，`1` 发送 |
| `sender_device_id` | `TEXT` | `NOT NULL` | 实际发送方设备 ID |
| `sender_name` | `TEXT` | `NOT NULL` | 发送方名称快照 |
| `content` | `TEXT` | `NOT NULL` | 聊天正文 |
| `sent_at` | `TEXT` | `NOT NULL` | 协议消息 UTC 时间 |
| `local_status` | `INTEGER` | `NOT NULL` | 本地状态快照 |
| `created_at` | `TEXT` | `NOT NULL` | 写入本地历史 UTC 时间 |

索引：

```sql
CREATE INDEX idx_chat_messages_peer_time
ON chat_messages(peer_device_id, sent_at DESC, message_id DESC);
```

### `transfer_history`

| 字段 | 类型 | 约束 | 说明 |
|:-----|:-----|:-----|:-----|
| `record_id` | `TEXT` | `PRIMARY KEY NOT NULL` | 历史记录 UUID |
| `session_id` | `TEXT` | `NOT NULL UNIQUE` | 传输会话 UUID，幂等写入键 |
| `peer_device_id` | `TEXT` | `NOT NULL`，外键到 `peer_devices(device_id)`，`ON DELETE RESTRICT` | 对端设备 ID |
| `peer_name` | `TEXT` | `NOT NULL` | 对端名称快照 |
| `direction` | `INTEGER` | `CHECK (direction IN (0, 1))` | `0` 接收，`1` 发送 |
| `display_name` | `TEXT` | `NOT NULL` | 文件或目录展示名 |
| `is_directory` | `INTEGER` | `CHECK (is_directory IN (0, 1))` | 是否目录传输 |
| `file_count` | `INTEGER` | `NOT NULL` | 文件数量 |
| `total_bytes` | `INTEGER` | `NOT NULL` | 总字节数 |
| `status` | `TEXT` | `NOT NULL` | 结束状态 |
| `started_at` | `TEXT` | `NOT NULL` | 开始 UTC 时间 |
| `finished_at` | `TEXT` | 可空 | 结束 UTC 时间 |
| `error_code` | `INTEGER` | 可空 | 失败错误码 |
| `error_message` | `TEXT` | 可空 | 失败说明 |

索引：

```sql
CREATE INDEX idx_transfer_history_peer_time
ON transfer_history(peer_device_id, started_at DESC, record_id DESC);

CREATE INDEX idx_transfer_history_status_time
ON transfer_history(status, started_at DESC);
```

## 数据库连接教程

### 应用内连接

业务代码不要直接在 QML 或 Controller 中写 SQL。正确链路：

```text
QML
  → AppController.historyController / chatController / transferController
  → HistoryController / ChatController / TransferController
  → LocalDataBroker
  → Repository 端口
  → Sqlite*Repository
  → SqliteDatabaseBroker
```

读取、写入、删除任务必须通过 `DatabaseWorker` 串行执行：

```cpp
_storageWorker->submitLoad(
    [this](SqliteDatabaseBroker &, QString *errorMessage) {
        const QList<PeerRecord> peers = _deviceRepository->recentPeers(10, errorMessage);
        return errorMessage->isEmpty();
    });
```

跨表写入必须使用短事务：

```cpp
return _database->runInTransaction(
    [&record](QSqlDatabase &database, QString *taskError) {
        QSqlQuery query(database);
        query.prepare("...");
        return query.exec();
    },
    errorMessage);
```

线程约束：

- 禁止跨线程传递 `QSqlDatabase`；
- 每个线程调用 `connectionForWorkerThread()` 获取自己的连接；
- 线程结束时调用 `closeConnectionForCurrentThread()`；
- 程序退出时先调用 `DatabaseWorker::beginShutdown()` 排空队列。

### 外部查看数据库

先退出应用，再使用 `sqlite3` 只读查看。Linux 常见路径：

```bash
sqlite3 "$HOME/.local/share/CQNU-SED/GridYard/database/gridyard-history.sqlite"
```

如果路径不确定：

```bash
find "$HOME" -path '*GridYard*database/gridyard-history.sqlite' -print
```

常用 SQL：

```sql
.tables
.schema peer_devices
.schema chat_messages
.schema transfer_history
PRAGMA foreign_key_check;

SELECT device_id, device_name, last_chat_at, last_transfer_at
FROM peer_devices
ORDER BY COALESCE(last_chat_at, last_transfer_at, last_seen_at) DESC;

SELECT peer_device_id, sender_name, content, sent_at
FROM chat_messages
ORDER BY sent_at DESC
LIMIT 20;

SELECT peer_device_id, peer_name, display_name, status, started_at, finished_at
FROM transfer_history
ORDER BY started_at DESC
LIMIT 20;
```

### 单机多实例历史归属

当前启动参数中，`--port` 只要被设置且没有显式 `--config`，程序会自动使用：

```text
/tmp/gridyard_config_<port>.ini
```

`device_id` 保存在配置文件里。如果临时配置文件被清理、端口变化或配置文件路径变化，就会生成新的 `device_id`。因为历史按对端 `device_id` 关联，UI 会表现为“重启后历史不见了”，但旧记录可能仍在数据库中。

稳定双实例测试应显式指定配置：

```bash
mkdir -p /root/GridYard/runtime

./build/Desktop_Qt_6_11_1-Debug/client/appGridYard \
  --config /root/GridYard/runtime/deviceA.ini \
  --port 35100 \
  --name "设备A" &

./build/Desktop_Qt_6_11_1-Debug/client/appGridYard \
  --config /root/GridYard/runtime/deviceB.ini \
  --port 35101 \
  --name "设备B" &
```

两个实例不能共用同一个 `--config`，否则两者 `device_id` 相同，发现服务会把对方当成本机广播过滤。

## 异常与降级

| 场景 | 行为 |
|:-----|:-----|
| 缺少 `QSQLITE` 驱动 | 初始化失败，`localHistoryAvailable=false`，P2P 主链路继续 |
| 空数据库首次启动 | 自动创建 schema_version 和 4 张业务表 |
| 重复 migration | 跳过已应用版本，不丢失已有数据 |
| 数据库锁定 | 当前任务失败并上报非阻塞提示，后续任务可重试 |
| 数据库损坏 | 备份为 `.corrupt-{timestamp}` 后重建空库 |
| 写入失败 | 不改变聊天或传输的网络结果，只提示历史可能缺失 |

日志只能记录操作类型、错误类别和脱敏标识，不记录聊天正文、完整 SQL、绑定参数或完整文件路径。
