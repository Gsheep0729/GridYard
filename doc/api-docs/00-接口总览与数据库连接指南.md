## 3. 命令行接口

文件：`src/client/main.cpp`

| 参数 | 示例 | 说明 |
|:-----|:-----|:-----|
| `--port <port>` | `--port 35100` | 覆盖本次运行的 TCP 监听端口 |
| `--name <name>` | `--name "设备A"` | 覆盖本次运行的显示名 |
| `--config <path>` | `--config /tmp/device-a.ini` | 指定 QSettings ini 配置文件路径 |
| `--help` | `--help` | 输出帮助 |
| `--version` | `--version` | 输出版本 |

重要约束：

- 当前实现中，如果指定 `--port` 但没有指定 `--config`，程序会自动使用 `/tmp/gridyard_config_<port>.ini`。
- `device_id` 保存在配置文件中；换配置文件或临时文件被清理，会生成新的 `device_id`。
- 聊天和传输历史按对端 `device_id` 关联，不按设备名或 IP 关联。
- 单机双实例测试必须给两个实例使用不同且稳定的 `--config` 文件。

推荐双实例启动：

```bash
mkdir -p /root/GridYard/runtime

./build/Desktop_Qt_6_11_1-Debug/client/appGridYard \
  --config /root/GridYard/runtime/deviceA.ini \
  --port 35100 \
  --name "设备A" &

./build/Desktop_Qt_6_11_1-Debug/client/appGridYard \
  --config /root/GridYard/runtime/deviceB.ini \
  --port 35101 \
  --name "设备B" &
```

不要让两个实例共用同一个配置文件，否则两者 `device_id` 相同，发现服务会把对方当作自己过滤掉。

## 5. SQLite 数据库设计

数据库路径：

```text
<QStandardPaths::AppDataLocation>/database/gridyard-history.sqlite
```

在当前应用设置下，`AppDataLocation` 由 Qt 根据应用名 `GridYard` 和组织名 `CQNU-SED` 生成。测试环境可通过 `ApplicationPaths::coverForTest()` 覆盖。

连接参数：

| PRAGMA | 值 | 说明 |
|:-----|:-----|:-----|
| `foreign_keys` | `ON` | 启用外键约束 |
| `journal_mode` | `WAL` | 使用 WAL，提高读写并发 |
| `synchronous` | `NORMAL` | 平衡性能和持久化安全 |
| `busy_timeout` | `5000` | 锁竞争最多等待 5 秒 |

### 5.1 表关系

```text
peer_devices
  ├─ 1:1 chat_conversations
  │      └─ 1:N chat_messages
  └─ 1:N transfer_history
```

## 6. 数据库连接教程

### 6.1 应用内连接方式

应用启动时由 `AppController` 初始化历史库：

```cpp
_storage->initialize(ApplicationPaths::databaseDir() + "/gridyard-history.sqlite", &storageError);
```

业务代码不要在 QML 或应用层直接写 SQL。正确路径：

```text
QML
  → AppController.history / AppController.chat / AppController.transfer
  → HistoryController / ChatManager / TransferSessionManager
  → Repository 接口
  → Sqlite*Proxy
  → SqliteDatabaseProxy
```

写入任务必须进入 `DatabaseWorker` 串行队列：

```cpp
_storageWorker->submitSave(
    [this, record](SqliteDatabaseProxy &, QString *errorMessage) {
        return _messageRepository->saveMessage(record, errorMessage);
    });
```

跨表写入使用 `runInTransaction()`：

```cpp
return _database->runInTransaction(
    [&record](QSqlDatabase &database, QString *taskError) {
        QSqlQuery query(database);
        // prepare / bind / exec
        return true;
    },
    errorMessage);
```

线程规则：

- 禁止跨线程传递 `QSqlDatabase`；
- 每个线程通过 `connectionForWorkerThread()` 获取自己的命名连接；
- Worker 线程结束前调用 `closeConnectionForCurrentThread()`；
- 退出应用时先排空 `DatabaseWorker` 队列，避免历史写入丢失。

### 6.2 外部只读查看数据库

先确认应用已退出，避免 WAL 中仍有未 checkpoint 的数据。然后使用 Qt 生成的数据目录下的数据库文件。

Linux 常见位置可这样查找：

```bash
find "$HOME" -path '*GridYard*database/gridyard-history.sqlite' -print
```

只读打开：

```bash
sqlite3 "$HOME/.local/share/CQNU-SED/GridYard/database/gridyard-history.sqlite"
```

常用查看命令：

```sql
.tables
.schema peer_devices
.schema chat_messages
.schema transfer_history
PRAGMA foreign_key_check;
SELECT * FROM schema_version;
```

查看最近聊天：

```sql
SELECT peer_device_id, sender_name, content, sent_at
FROM chat_messages
ORDER BY sent_at DESC
LIMIT 20;
```

查看最近传输：

```sql
SELECT peer_device_id, peer_name, display_name, status, started_at, finished_at
FROM transfer_history
ORDER BY started_at DESC
LIMIT 20;
```

### 6.3 单机多实例与历史归属排查

历史记录按“对端 `device_id`”归属：

- A 机本地数据库中，和 B 的聊天记录使用 B 的 `device_id`；
- B 机本地数据库中，和 A 的聊天记录使用 A 的 `device_id`；
- 设备名、IP、端口变化不会迁移历史；
- `device_id` 变化会让 UI 看起来像历史丢失。

排查步骤：

1. 打开设置页或日志，确认当前 `ConfigManager.deviceId`；
2. 检查启动命令是否指定了稳定的 `--config`；
3. 查询数据库中是否存在旧对端 ID：

```sql
SELECT device_id, device_name, last_ip_address, last_tcp_port, last_chat_at, last_transfer_at
FROM peer_devices
ORDER BY COALESCE(last_chat_at, last_transfer_at, last_seen_at) DESC;
```

如果使用了 `--port` 但没有 `--config`，当前实现会自动使用 `/tmp/gridyard_config_<port>.ini`。临时配置被清理后会生成新 `device_id`，旧历史仍在库中，但不会挂到新设备卡片下。

### 6.4 损坏库与 WAL 文件

初始化时如果发现 SQLite 文件损坏，系统会：

1. 关闭当前连接；
2. 将旧库重命名为 `gridyard-history.sqlite.corrupt-<UTC时间戳>`；
3. 同步尝试备份 `-wal` 和 `-shm` 旁路文件；
4. 重建空库并重新执行迁移。

WAL 模式下，数据库文件组包括：

```text
gridyard-history.sqlite
gridyard-history.sqlite-wal
gridyard-history.sqlite-shm
```

备份、拷贝或人工检查时应把三个文件作为同一组处理。应用内测试重开同一库前需要 checkpoint 或显式关闭连接，避免刚写入的数据仍在 WAL 中。

## 7. 典型 QML 调用示例

刷新附近设备：

```qml
ToolButton {
    icon.name: "view-refresh"
    onClicked: AppController.discovery.refresh()
}
```

发送聊天消息：

```qml
AppController.chat.sendText(deviceId, messageInput.text)
```

加载更早聊天记录：

```qml
AppController.history.loadMoreMessages(deviceId)
```

查询当前设备传输历史：

```qml
AppController.history.queryTransfers({
    "deviceId": deviceId,
    "status": "completed"
})
```

创建传输任务：

```qml
AppController.transfer.createSendSession(deviceId, filePath)
```

清空当前设备已结束传输记录：

```qml
AppController.transfer.clearFinishedSessions(false, deviceId)
```

设置历史保留天数：

```qml
AppController.history.setRetentionDays(30)
```

## 8. 维护规则

- 新增 QML 可调用接口时，同步更新本文第 2 节和对应模块文档；
- 新增数据库表、字段、索引或迁移版本时，同步更新本文第 5 节和 `08-本地数据层模块.md`；
- 新增命令行参数时，同步更新本文第 3 节、README 和测试指南；
- QML/UI 层不得直接访问 SQL；
- 应用逻辑层只依赖 Repository 端口和值对象；
- 任何 `device_id` 生成、配置隔离、历史恢复相关变更，都必须说明对本地历史归属的影响。
